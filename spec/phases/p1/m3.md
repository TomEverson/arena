# M3. Movement on the server + shared test vectors

**Phase:** 1 (FFA Deathmatch) · **Status:** done (client and server both pass the shared vectors) · **Depends on:** M1

## Scope
- [x] Port movement to `server/internal/game/movement.go` (float64)
- [x] Record vectors from the TS implementation into `testvectors/` (initial state, inputs, dt, expected state)
- [x] Go and Vitest both run the same vector files (`pnpm test` fails on drift; CI wiring deferred on purpose)
- [x] Server loads the same level JSON and applies player inputs each tick
- [x] Cover slide, dash, mantle, ramps, wall and corner collisions

## Done when
Both suites pass identical vectors, and a player driven by inputs moves the same on server and client.

## What was built
- **`shared/`** (`@arena/shared`): `params.json` is the single source of truth for movement and weapon numbers. TypeScript imports it directly; Go constants are generated into `server/internal/game/params_gen.go` (`pnpm gen`), and `pnpm test` fails if the generated file is stale.
- **Vector format and recorder** (`client/src/sim/vectors/`, `client/scripts/record-vectors.ts`): 38 scenarios recorded to `testvectors/movement/*.json` by `pnpm vectors`, each guarded by a `verify`.
- **Go movement port** (`server/internal/game/movement.go`, `collision.go`, `types.go`): line-for-line port of the TS sim; allocation-free.
- **Go level loader** (`server/internal/level`): reads the same `levels/*.json`. The server takes `--level` (default `../levels/greybox.json`) and spawns players at the level's spawn zones in turn.
- **Server input handling**: a fixed per-player queue (16 inputs). Exactly one input is simulated per tick. When the queue is empty, the last input repeats with jump/dash presses cleared. When full, the oldest inputs are dropped. Snapshots carry real `x, y, z` and `ackSeq`.
- **Verification**: vectors run through `StepPlayer` directly and through the real `World` (join, queue, step). `TestStepDoesNotAllocateWithMovingPlayers` keeps the zero-allocation rule honest with 8 players using every move on the greybox level. A live smoke test (WebSocket client, real server) moved, jumped and dashed a player and returned acks.
- **Turborepo** knows `testvectors/`, `levels/` and `shared/` are test inputs, so changing them re-runs the suites instead of replaying a cached result.

## Not in M3
- The browser client does not send inputs yet (M4: prediction, reconciliation, interpolation).
- Weapons and hit detection on the server (M5).
- CI wiring (`.gitlab-ci.yml` is untouched, by request).

## Known limits
See `testvectors/README.md`: threshold changes can slip past vectors; JS/Go last-bit differences are absorbed by the 1e-6 tolerance. Input-queue policy (one per tick, drop oldest) is the simplest thing that works; M4 will revisit it when real network jitter appears.

## Notes
From here on, any movement change must update `testvectors/` (AGENTS.md hard rule). Bit-exact equality is not required; use a small tolerance.
